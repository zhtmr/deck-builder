녹음은 12단계를 거쳐 회의록이 된다

업로드는 브라우저가 스토리지로 직접 보내고, 무거운 STT·요약은 Kafka 뒤의 워커가 비동기로 처리합니다.

  1. 1
    브라우저 녹음기 → Nginx
    녹음 종료 후 업로드 URL 요청
  2. 2
    Nginx → API 서버
    POST /api/uploads/presign — Presigned URL 발급
  3. 3
    브라우저 녹음기 → MinIO
    오디오를 API 서버를 거치지 않고 MinIO에 직접 업로드
  4. 4
    API 서버 → Kafka
    complete 호출 시 stt.requested 이벤트 발행
  5. 5
    Kafka → STT 워커
    STT 워커가 이벤트 수신
  6. 6
    STT 워커 → MinIO
    오디오 파일 다운로드 후 faster-whisper 전사
  7. 7
    STT 워커 → Claude API
    전사문을 Claude로 요약해 회의록 초안 생성
  8. 8
    STT 워커 → Kafka
    결과를 stt.completed로 발행
  9. 9
    Kafka → API 서버
    API 서버가 결과 수신
  10. 10
    API 서버 → PostgreSQL
    회의록 저장
  11. 11
    API 서버 → Nginx
    SSE로 브라우저에 완료 알림
  12. 12
    API 서버 → Slack
    Slack 채널에 회의록 링크 공유
→ 키로 한 단계씩. 3번(직접 업로드)과 4번(비동기 분리)에서 멈춰 설계 이유 설명.

워커는 상태 없이 이벤트만 처리하므로 GPU 서버를 늘리면 수평 확장됩니다.

  • 오디오 바이트는 API 서버를 통과하지 않음
  • 완료 신호만 받아 stt.requested 발행
  • 요청은 즉시 반환 — 처리 진행은 SSE로 통지
결정 2: Presigned URL 로 직접 업로드. API 서버는 완료 신호만 받아 이벤트를 발행한다.
